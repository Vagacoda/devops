# Week 12 - GitHub Actions

## CI와 CD

- CI는 코드 변경을 자동으로 검사하고 테스트하고 빌드한다.
- CD는 검증된 결과물을 배포 가능한 상태로 만들거나 실제 환경에 배포한다.

## GitHub Actions 구성

- workflow: 자동화 작업을 정의한 YAML 파일
- trigger: 워크플로가 실행되는 조건
- job: 러너에서 실행되는 작업 묶음
- step: job을 구성하는 개별 단계
- runner: 작업이 실행되는 컴퓨터

## 실습 결과

- Ruff 린트와 unittest 테스트 2개를 통과했다.
- PR에서는 검사와 이미지 빌드를 실행했다.
- main에서는 검사를 통과한 이미지를 GHCR에 게시했다.
- 커밋 태그 917d200 이미지를 Minikube에 배포했다.
- GHCR 쓰기 권한 오류가 발생해 패키지의 Actions 접근 권한을 수정했다.

## 실패 실험

- 문법 오류를 추가해 CI 실패를 확인했다.
- APP_TITL 오타는 문법 검사를 통과했지만 Ruff에서 F821 오류로 발견했다.
- /healthz 응답을 500으로 바꾸자 테스트에서 500 != 200으로 실패했다.
- 오류를 수정하고 push하자 검사가 다시 초록색으로 통과했다.

## 브랜치 보호

- main에 직접 변경을 올리는 대신 PR을 사용한다.
- 필수 build 검사가 실패하면 PR 병합이 차단된다.
